Xiyue Container

家里的那一半

音乐服务和汐墨阅读，放在自己的 NAS 上。

一个 compose 就能装

这份 compose 同时启动两个服务：xiyue 提供懂你推荐、说一句找歌和代下载，使用 8790 端口；reader 是汐墨阅读服务，使用 8791 端口。

在支持 Docker Compose 的设备上新建文件夹，把下面的内容保存为 compose.yaml，只把第一行改成自己的音乐目录。保留文件夹里的数据目录，重新创建容器时才能继续使用原来的设置和书架。

同一音乐目录会以只读方式用于分析，也以可写方式用于代下载和需要写入的标签；请确认该目录可由容器写入。

compose.yaml
x-music: &music "/改成你的音乐目录"

services:
  xiyue:
    image: bbong9/xiyue-taste:latest
    pull_policy: always
    environment:
      TASTE_ACCESS_TOKEN: "${TASTE_ACCESS_TOKEN:-}"
      TASTE_LLM_API_KEY: "${TASTE_LLM_API_KEY:-}"
      TASTE_LLM_MODEL: "${TASTE_LLM_MODEL:-deepseek-ai/DeepSeek-V3.2}"
    volumes:
      - { type: bind, source: *music, target: /music, read_only: true }
      - { type: bind, source: *music, target: /downloads }
      - ./data:/data
      - ./out:/out
    ports:
      - "8790:8790"
    cpus: "2.0"
    mem_limit: 2g
    restart: unless-stopped

  reader:
    image: bbong9/xiyue-reader:1.0.40
    environment:
      TZ: Asia/Shanghai
      READER_APP_STORAGEPATH: /storage
      READER_APP_SECURE: "true"
      READER_APP_SECUREKEY: "${READER_APP_SECUREKEY:-}"
      READER_APP_INVITECODE: "${READER_APP_INVITECODE:-}"
      READER_APP_USERLIMIT: "${READER_APP_USERLIMIT:-50}"
      READER_APP_USERBOOKLIMIT: "${READER_APP_USERBOOKLIMIT:-200}"
      LOGGING_PATH: /logs
    volumes:
      - ./reader/storage:/storage
      - ./reader/logs:/logs
    ports:
      - "8791:8080"
    restart: unless-stopped

启动和升级

在 compose.yaml 所在目录执行 docker compose up -d。飞牛用户也可以在容器管理页面新建 compose 项目、填写同一份内容并启动；确认选择拉取镜像，不需要在设备上构建源码。

升级时先执行 docker compose pull，再执行 docker compose up -d。音乐服务使用 latest；阅读服务使用 1.0.40，想升级到其他版本时先将示例里的版本号改成你确认可用的版本。

音乐服务的设置和账号在 ./data，分析结果在 ./out，下载写入选定的音乐目录；阅读账号、书架、书源和进度在 ./reader/storage，日志在 ./reader/logs。汐墨容器内的数据路径必须保持 /storage，不要改右侧的挂载路径。

音乐面板设置

第一次在家里用设备的内网地址和 8790 端口打开音乐面板，依次设置「连接设置」、主账户和家人账户；需要在线音源时自行导入插件。面板的访问口令可在连接设置中填写，离家用浏览器打开面板时使用。

「AI 设置」可选，不配置 AI 密钥时，「说一句找歌」按歌名、歌手搜索已分析的本地曲库。使用 AI 时，你的话和相关曲库文字会发给你配置的服务。

路径与可选环境变量

原部署配置中的 MUSIC_DIR、OUT_DIR、DOWNLOAD_DIR 分别表示音乐目录、分析结果目录和代下载目录。本页示例直接使用第一行音乐目录及 ./out，不读取这三个变量；要改位置，请修改对应挂载。

TASTE_ACCESS_TOKEN 是音乐面板的访问口令，TASTE_LLM_API_KEY 是可选 AI 密钥，TASTE_LLM_MODEL 是 AI 模型名。这些值可以不通过环境变量填写，改在音乐面板设置；没有 AI 密钥时只能按曲库查找，未设置面板访问口令时不提供口令访问。模型未设置时使用 deepseek-ai/DeepSeek-V3.2；面板保存的设置优先。

汐墨的 READER_APP_SECURE 开启多用户；READER_APP_SECUREKEY 是管理密码，READER_APP_INVITECODE 是注册邀请码，READER_APP_USERLIMIT 和 READER_APP_USERBOOKLIMIT 分别是账号数和每个账号的书数上限。示例默认开启多用户，上限分别为 50 和 200。

管理密码和邀请码可留空：留空时无法使用需要管理密码的用户管理操作，注册也不需要邀请码。要限制注册或启用管理操作，需在部署工具的环境变量中提供相应值并重新创建阅读服务；这两项不能在汐墨网页面板中设置。

需要「存入小说库」时，管理员在汐墨「我的 → 管理模式 → 用户管理」为相应账号开启「本地书仓」；默认小说库在书仓的「小说库」子目录，管理模式中可以更改位置。

汐月账号与家人共用

在音乐面板设置主账户，再为家人各建一个账户。在 App 的「设置 → 汐月账号」填写容器内网地址及端口，或可用的 HTTPS 外网地址，再用各自的名字和密码登录。已经连接飞牛音乐时，内网地址沿用飞牛所在设备；没连接飞牛时自行填写。面板访问口令与 App 登录密码不同，App 不需要手填面板访问口令。

每个人的收听记录、喜欢和歌单各自保存；一个音乐账户同时只能在一台手机上登录。阅读服务另有自己的账号，在「设置 → 阅读」连接后于汐墨页面登录。

代下载与测响度

选「下载到 NAS」时，容器会直接下载歌曲、歌词和封面存进音乐库，手机可以锁屏离开；容器下不了时，手机会接手下载再上传。

容器每天自动测量新歌的响度，也可以在面板里手动测。

端口、拉取和口令

提示端口被占用时，把 compose 端口映射左侧的数字改为未被使用的端口，右侧的 8790 或 8080 保持不变；App 里也填写修改后的对应内网端口。

飞牛上拉取失败时，检查设备网络、镜像名称和版本是否可用，再在容器管理页面重新拉取；安装方式使用镜像，不选择本地构建。

音乐面板在外网提示无权访问时，检查面板口令；App 提示「名字或密码不对」时，检查音乐账号，不要把面板口令当成账号密码。汐墨注册提示邀请码错误时，请向服务管理员确认邀请码。

示例中的汐墨没有邀请码，能访问阅读页面的人可以注册；如需限制注册，先配置邀请码并控制服务的访问范围。

扫描后没有导出歌曲

容器 1.8.14 起，扫描后导出 0 首歌时，日志和面板会区分「没有找到音频文件」和「音频全部分析失败」。先按提示检查音乐目录或分析错误，再重新扫描。
